# 寫作風格詳細分析

## 語調分析

### 特徵
- **第一人稱視角**：常用「我」、「我的」建立親密感
- **親身故事**：分享個人學習歷程和經驗
- **謙遜開放**：主動承認學習者身分，邀請讀者指正

### 範例

❌ 不符合風格的寫法：
> React 是一個用於構建用戶界面的 JavaScript 庫。Facebook 開發並開源。

✅ 符合風格的寫法：
> 這裡將會記錄我學習 React 的筆記。我發現很多開發者像我一樣，對如何高效使用 React 感到困惑。

## 結構模式

### 典型的文章結構
1. **視覺吸引**：首圖 + 標題
2. **個人引入**：為什麼寫這篇、背景故事（1-2 段）
3. **核心內容**：層級分明的章節，每章都有重點
4. **視覺支援**：圖、表、代碼高亮
5. **總結反思**：回顧要點，邀請互動

### 層級標題規則
- H1 (#)：只用一次，在文章開頭
- H2 (##)：章節分隔
- H3 (###)：子主題或小節
- H4 及以下：根據需要

## 類比與譬喻

### 為什麼使用類比？
- 降低理解難度
- 讓抽象概念具體化
- 增加記憶深度
- 提升文章可讀性

### 類比的來源
- 日常生活（師生互動、家庭類比）
- 真實工作場景
- 物理世界的運作原理

### 範例集合

| 技術概念 | 日常類比 |
|--------|--------|
| 命令式 vs 聲明式 | 老師口渴時的互動方式 |
| 虛擬 DOM | 草稿紙 vs 最終版本 |
| 組件化 | 積木或樂高 |
| 模組化 | 專業分工 |

## 視覺化策略

### 圖片使用原則
- **第一圖**：首圖，代表文章主題或系列
- **引導圖**：複雜概念前放示意圖或架構圖
- **對比圖**：展示「之前 vs 之後」、「好 vs 不好」
- **步驟圖**：GIF 或序列截圖展示操作
- **截圖標註**：用箭頭或框框強調重點

### 表格使用場景
- 工具對比（功能清單）
- 命令或快捷鍵集合
- 概念分類
- 時間表或進度表

## 系列化寫作

### 系列的優勢
- 讀者可以系統學習
- 內容更容易組織
- 系列建立品牌認知

### 系列類型

**1. 連貫進階系列**（如 React 指南）
- 每篇獨立，但相互依賴
- 前置知識清單
- 可跳過某些篇章

**2. 每日挑戰系列**（如 30 天挑戰）
- 30 篇文章，每篇相對完整
- 每天推進同一主題
- 格式保持一致

**3. 主題深入系列**
- 圍繞同一主題的多個角度
- 無強制順序
- 可獨立閱讀

## 前置知識聲明

重要的做法：明確指出讀者應具備的基礎

**範例：**
```markdown
## 學習 React 所需要的 Javascript 知識

- [x] 判斷 this 指向
- [x] class 的概念
- [x] ES6 的語法規範
- [x] npm 套件管理工具
```

優點：
- 幫助讀者自我評估
- 減少困惑
- 設定清楚的期望

## 實用內容的特點

### 包含的具體元素
- ✅ 實際操作步驟（含圖示）
- ✅ 推薦的工具清單
- ✅ 快捷鍵速查表
- ✅ 代碼範例和片段
- ✅ 常見錯誤和解決方案

### 避免的做法
- ❌ 純理論堆砌
- ❌ 過於高級的術語未解釋
- ❌ 沒有實際應用場景
- ❌ 無法立即嘗試的內容

## 語言細節

### 標題風格
- **有趣且資訊豐富**
  - ✅ 「工欲善其事，必先利其器」
  - ✅ 「React - 簡介」
  - ❌ 「簡介」
  - ❌ 「第一堂課」

### 段落風格
- 使用短句（15-20 字最佳）
- 重要概念用**粗體**或 `代碼` 高亮
- 列表項目簡潔清晰
- 避免複雜的嵌套句子

### 中文用語慣例
- 使用「繁體中文」
- 尊重台灣用語習慣
- 技術術語保留英文（如 DOM、React、JavaScript）
- 專有名詞首次出現時，可附註英文或解釋

## 互動與反饋機制

### 開放態度
- 主動邀請讀者指正
- 表達歡迎建議的態度
- 感謝讀者的參與

### 範例措辭
> 如果有發現內容有誤，也請您不吝指教，感謝。

> 也歡迎大家在下面留言補充更多好玩好用的套件～

## 常見模式識別

### 「為什麼」三層次
1. **問題層**：原生方式的痛點
2. **解決層**：新技術/方法如何解決
3. **應用層**：實際使用的場景

### 「前言 → 內容 → 總結」模式
- 前言：建立個人連結和背景
- 內容：分層展開核心知識
- 總結：回顧重點，展望或邀請互動

---

## 質量檢查維度

| 維度 | 檢查項 | 好的標準 |
|-----|-------|--------|
| 清晰度 | 一個不熟悉的人能理解嗎？ | 能完整理解核心概念 |
| 視覺性 | 圖表是否充分？ | 每 300 字至少 1 張圖 |
| 實用性 | 讀者能立即應用嗎？ | 提供具體步驟或代碼 |
| 人性化 | 是否有個人聲音？ | 能感受到作者的親切感 |
| 完整性 | 是否需要外部資源？ | 前置知識清楚標明 |
