# 寫作檢查清單 - 使用指南

使用此清單在發佈前檢查您的文章。每個項目都與您的風格特徵對應。

## ✅ 前期準備

- [ ] 確定文章主題和目標讀者
- [ ] 蒐集相關圖片（至少 3-5 張）
- [ ] 準備代碼範例或實際操作截圖
- [ ] 規劃文章的主要章節

## ✅ 核心內容檢查

### 語調與人設
- [ ] 使用了第一人稱「我」來建立連結
- [ ] 展現個人經歷或學習過程
- [ ] 表達了謙遜開放的態度
- [ ] 邀請讀者互動或指正

### 結構完整性
- [ ] 有吸引人的前言（為什麼要寫、個人背景）
- [ ] 有清晰的 H2 標題分隔章節
- [ ] 有明確的 H3 標題標示子主題
- [ ] 有總結段落（回顧重點 + 邀請互動）

### 概念講解
- [ ] 每個主要概念前都有「為什麼」的說明
- [ ] 使用了至少 1-2 個日常類比或例子
- [ ] 概念由簡至繁，循序漸進
- [ ] 複雜概念用多種方式解釋（文字 + 圖 + 例子）

### 實用性
- [ ] 提供了具體的操作步驟
- [ ] 包含了實際可用的代碼或配置
- [ ] 共享了推薦的工具或資源
- [ ] 讀者可以立即嘗試或應用

## ✅ 視覺化檢查

- [ ] 有首圖（Open Graph 圖像）
- [ ] 至少有 3-5 張相關圖片或圖表
- [ ] 複雜概念配有示意圖或架構圖
- [ ] 操作流程用 GIF 或截圖展示
- [ ] 圖片都有適當的標題或說明
- [ ] 表格用於整理多項資訊
- [ ] 所有圖片 URL 都正確可訪問

## ✅ 寫作品質

### 文字質量
- [ ] 標題有表現力且資訊豐富
- [ ] 段落長度適中（避免過長或過短）
- [ ] 重點內容用**粗體**、`代碼` 或 - 清單突出
- [ ] 避免複雜的嵌套句子

### 語言與措辭
- [ ] 使用繁體中文
- [ ] 技術術語保留英文
- [ ] 遵循台灣用語習慣
- [ ] 標點符號使用正確

### 格式一致性
- [ ] 代碼區塊有語言標記（markdown、javascript 等）
- [ ] 內部連結使用相對路徑
- [ ] 外部連結有 `[文字](url)` 格式
- [ ] 縮排和空白符合 Markdown 規範

## ✅ Metadata 檢查

- [ ] `title` 有表現力（不只是主題名）
- [ ] `description` 是完整的一句話摘要
- [ ] `pubDate` 格式正確（YYYY-MM-DD）
- [ ] `tags` 包含 2-4 個相關標籤
- [ ] `image` URL 有效且相關
- [ ] （如適用）`series` 正確對應系列名稱

## ✅ 系列文章額外檢查

- [ ] 前置知識清單清晰標明
- [ ] 與系列中其他文章風格一致
- [ ] 有適當的過渡性提示（「上一篇」「下一篇」）
- [ ] Series slug 與其他文章一致

## ✅ 最終審查

- [ ] 通讀全文，檢查流暢性
- [ ] 檢查是否有語法錯誤或打字錯誤
- [ ] 驗證所有外部連結可訪問
- [ ] 確認圖片都能正確顯示
- [ ] 在本地預覽呈現效果

## 📊 自評打分

完成以上檢查後，評估您的文章：

| 分數 | 評估 | 行動 |
|-----|-----|-----|
| 90-100 | 優秀，準備發佈 | ✅ 發佈 |
| 80-89 | 良好，小調整 | 🔄 修改後發佈 |
| 70-79 | 中等，需改進 | ⚠️ 重新檢查 |
| <70 | 需要較大改動 | 🔙 重新起稿或大幅修改 |

---

## 💡 快速提示

- **視覺化不足？** 回頭補充圖片
- **太理論？** 加入具體例子或操作步驟
- **不夠親切？** 增加個人故事或「我」的用語
- **結構散亂？** 檢查標題層級和邏輯連接
- **前言無力？** 寫得更具體、更個人化
