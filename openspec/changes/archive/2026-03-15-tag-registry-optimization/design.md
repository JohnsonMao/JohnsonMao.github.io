## Context

目前部落格的標籤管理僅透過字串 ID 進行，且散落在各個文章目錄的 `_meta.ts` 中。這導致在不同語系下無法顯示翻譯後的標籤名稱，且拼寫錯誤難以在建置階段發現。

## Goals / Non-Goals

**Goals:**

- 實作單一來源的標籤定義檔。
- 在撰寫文章時提供型別保護。
- 在建置時自動驗證標籤有效性。
- 支援標籤名稱的多語系顯示。

**Non-Goals:**

- 不實作標籤的動態分類或層級（目前維持扁平 ID）。
- 不改變現有的標籤路由 URL 結構（維持使用標籤 ID）。

## Decisions

### 1. 標籤註冊表格式 (Registry Format)
- **決策**：使用 TypeScript (`src/data/tags.ts`) 而非 JSON。
- **理由**：TypeScript 可以直接匯出 `TagId` 型別供 `_meta.ts` 引用，提供開發時的自動補全與錯誤檢查。
- **替代方案**：JSON 檔。雖然易於閱讀，但需要額外的步驟來產生 TypeScript 型別。

### 2. 強制型別約束 (Strict Typing)
- **決策**：要求所有 `_meta.ts` 檔案顯示標註 `: TagId[]`。
- **理由**：將錯誤發現在撰寫當下，而非建置時。

### 3. 建置時斷言 (Build-time Assertion)
- **決策**：在 `src/utils/content.ts` 載入內容時，比對標籤 ID 是否存在於註冊表中。
- **理由**：作為最後一道防線，防止未通過型別檢查的內容進入生產環境。

## Risks / Trade-offs

- **[Risk]**：新增標籤時需要多一個步驟（在 `tags.ts` 註冊）。 → **Mitigation**：這是為了維護質量所必要的成本，且透過型別報錯能引導開發者完成註冊。
- **[Risk]**：標籤顯示名稱的維護。 → **Mitigation**：集中管理比分散管理更容易進行全面審閱。
